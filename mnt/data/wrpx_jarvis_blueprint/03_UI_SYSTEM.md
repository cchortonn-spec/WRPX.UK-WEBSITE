# 03 — UI System

## Purpose of this file

This document defines the visual and interaction direction for Jarvis.

Jarvis is not a collection of tools. Jarvis is the operating system of WRPX. The UI should feel like one connected business command centre.

---

# Overall style

Jarvis should look premium, dark, modern, and calm.

It should feel like a serious commercial business system, not a generic CRM.

Preferred style:

- dark green glass UI
- not pure black
- subtle depth
- soft borders
- glass cards
- green accents
- pill badges
- clean tables
- beautiful spacing
- Apple-like motion
- responsive layouts
- no harsh neon
- no blue/purple glowing SaaS look

---

# Colour direction

Base:

- charcoal green/black
- deep graphite
- dark glass panels

Accent:

- WRPX lime/green
- subtle pink only where already part of brand/analytics
- amber/red for warnings
- muted slate for inactive/lost states

Avoid:

- bright blue SaaS styling
- purple glow effects
- heavy gradients unless subtle
- cluttered dashboards

---

# Layout principles

Every screen should answer a business question.

Dashboard:

> What needs Connor's attention today?

Leads:

> Who needs progressing?

Pipeline:

> Where is every opportunity stuck?

Finance:

> Where is the money?

Jobs:

> What work needs doing?

Analytics:

> Where are leads coming from and what should improve?

---

# Components

Use consistent components across Jarvis:

- glass cards
- stage pills
- priority badges
- compact stat cards
- lead/project cards
- slide-over drawers
- full-screen mobile sheets
- timeline/activity rows
- quick action buttons
- status indicators
- empty states
- search/filter bars

---

# Stage colours

Use subtle pill colours, not harsh blocks.

Recommended colours:

- New Lead — grey/slate
- Waiting for Photos — amber
- Photos Received — teal
- Waiting for Colour / Job Type — orange
- Ready to Price — lime green
- Estimate Sent — soft green
- Survey Booked — cyan
- Measured — violet, muted
- Quote Sent — pink, muted
- Follow Up — amber/red
- Won — green
- Lost — muted red
- Not Suitable — slate

Colour should support recognition, not dominate the UI.

---

# Mobile UI rules

Mobile is critical.

Connor will use Jarvis on iPhone while out working.

Mobile requirements:

- large buttons
- quick add note
- quick add reminder
- quick stage update
- quick photo upload
- camera/gallery upload
- bottom action bars where helpful
- full-screen drawers instead of cramped side drawers
- horizontal scroll for kanban
- readable cards
- minimal typing
- sticky save buttons
- clear confirmation after actions

Desktop can be information-rich.
Mobile must be action-fast.

---

# Animation direction

Animations should feel subtle and iOS-like.

Use:

- smooth drawer transitions
- soft hover states
- gentle scale on press
- subtle loading shimmer
- no dramatic bounces
- no distracting movement

Motion should make Jarvis feel premium, not gimmicky.

---

# Jarvis presence in UI

Jarvis should feel present throughout the system.

Not just one chat box.

Examples:

- Jarvis briefing on home dashboard
- Jarvis insight cards
- Jarvis warning badges
- Jarvis recommendations inside drawers
- Jarvis suggested next actions
- Jarvis generated summaries
- Jarvis daily priorities

Use wording like:

- Jarvis says
- Jarvis recommends
- Jarvis has noticed
- Jarvis priority

Keep tone calm and useful.

---

# Empty states

Empty states should be helpful.

Example:

> No follow-ups due today.
> Jarvis will flag anything that needs attention.

Do not use generic empty states.

---

# Forms

Forms should be fast and friendly.

Do not overwhelm the user.

Use:

- grouped sections
- sensible defaults
- quick action chips
- mobile-friendly inputs
- clear save states
- inline validation

---

# Design rule

Before building any UI, ask:

1. Is this fast on mobile?
2. Does this match the WRPX/Jarvis visual system?
3. Does this help Connor know what to do next?
4. Does this feel like part of one operating system?
5. Can this scale to future staff and subcontractors?
